# Datasets

This folder contains the image datasets used for GP model fitting.

## Setup

NPZ files are git-ignored (too large). The symlink to the original dataset must be created locally:

```bash
cd datasets/
ln -s ../../../notebooks/PNAS_paper_sorted_data.npz PNAS_108x108_original.npz
```

## Available Datasets

| File | Size | Source | Description |
|------|------|--------|-------------|
| `PNAS_108x108_original.npz` | 108x108 | Symlink to `notebooks/PNAS_paper_sorted_data.npz` | Original full-resolution PNAS images |
| `PNAS_64x64_center_crop_no_renorm.npz` | 64x64 | Generated by `create_cropped_dataset.py` | Center-cropped, NOT re-normalized |

## Generating Cropped Datasets

```bash
python create_cropped_dataset.py --crop-size 64
```

This produces `PNAS_64x64_center_crop_no_renorm.npz`. To use it for training:

```bash
cd ..  # back to gpytorch_porting/
python run_single_mode.py --data-path datasets/PNAS_64x64_center_crop_no_renorm.npz
```

## No Re-Normalization Policy

Cropped datasets keep the **original pixel values** from the full 108x108 images. They are NOT re-normalized after cropping.

Why: The neuron saw images that were normalized across the full 108x108 frame. The pixel values encode the physical stimulus intensity the neuron responded to. Re-normalizing after cropping would change the mapping between pixel values and neural responses, breaking the scientific interpretation.

Consequence: The cropped images will have slightly different mean/std than the full images (since border pixels are removed), but each pixel retains its original value.

## NPZ Format

All datasets use identical keys (compatible with `load_pnas_data()`):
- `images_train`: (N_train, H, W, 1) float32
- `images_val`: (N_val, H, W, 1) float32
- `images_test`: (N_test, H, W, 1) float32
- `responses_train`: (N_train, 41) float64
- `responses_val`: (N_val, 41) float64
- `responses_test`: (30, 30, 41) float64

The pipeline auto-detects `n_px_side` from the image shape (H == W).
