# Datasets

This folder contains the image datasets used for GP model fitting.

## Setup

NPZ files are git-ignored (too large). The symlink to the original dataset must be created locally:

```bash
cd datasets/
ln -s ../../../notebooks/PNAS_paper_sorted_data.npz PNAS_108x108_original.npz
```

## Available Datasets

| File | Size | Source | Description |
|------|------|--------|-------------|
| `PNAS_108x108_original.npz` | 108x108 | Symlink to `notebooks/PNAS_paper_sorted_data.npz` | Original full-resolution PNAS images |
| `PNAS_64x64_center_crop_no_renorm.npz` | 64x64 | Generated by `create_cropped_dataset.py` | Center-cropped (offset=22), NOT re-normalized |
| `PNAS_48x48_center_crop_no_renorm.npz` | 48x48 | Generated by `create_cropped_dataset.py` | Center-cropped (offset=30), NOT re-normalized |
| `rf_centers_ground_truth.npz` | — | Derived from `samuele_data/lsta_ref.npz` | Ground-truth RF centers for all 41 cells |

## Generating Cropped Datasets

```bash
python create_cropped_dataset.py --crop-size 64
```

This produces `PNAS_64x64_center_crop_no_renorm.npz`. To use it for training:

```bash
cd ..  # back to gpytorch_porting/
python run_single_mode.py --data-path datasets/PNAS_64x64_center_crop_no_renorm.npz
```

## No Re-Normalization Policy

Cropped datasets keep the **original pixel values** from the full 108x108 images. They are NOT re-normalized after cropping.

Why: The neuron saw images that were normalized across the full 108x108 frame. The pixel values encode the physical stimulus intensity the neuron responded to. Re-normalizing after cropping would change the mapping between pixel values and neural responses, breaking the scientific interpretation.

Consequence: The cropped images will have slightly different mean/std than the full images (since border pixels are removed), but each pixel retains its original value.

## RF Reference Centers (from white noise/checkerboard stimulation)

`rf_centers_ground_truth.npz` contains ground-truth RF centers for all 41 cells, derived from RF ellipse fits obtained via white noise/checkerboard stimulation. Source: `samuele_data/lsta_ref.npz` (the `ellipses` array — NOT the `lsta` array, which is from a different measurement).

The ellipses give precise RF positions independent of our GP model's STA computation.

**Coordinate mapping**: The LSTA uses a 72x72 grid covering the same field of view as the 108x108 images. Mapping: `pixel_108 = pixel_72 * 1.5`. Center crops use their respective offsets: `pixel_64 = pixel_108 - 22`, `pixel_48 = pixel_108 - 30`.

| Key | Shape | Description |
|-----|-------|-------------|
| `centers_72` | (41, 2) | RF centers in 72x72 LSTA pixel coords (cx, cy) |
| `centers_108` | (41, 2) | RF centers in 108x108 pixel coords |
| `centers_64` | (41, 2) | RF centers in 64x64 pixel coords |
| `centers_48` | (41, 2) | RF centers in 48x48 pixel coords |
| `norm_108` | (41, 2) | Normalized [-1, 1] coords for 108x108 |
| `norm_64` | (41, 2) | Normalized [-1, 1] coords for 64x64 |
| `norm_48` | (41, 2) | Normalized [-1, 1] coords for 48x48 |

Usage:
```python
rf = np.load('datasets/rf_centers_ground_truth.npz')
eps_0x, eps_0y = rf['norm_108'][cell_id]  # for 108x108 training
```

Source data: `samuele_data/lsta_ref.npz` (LSTA frames + ellipse contours, 72x72 grid).

## NPZ Format

All datasets use identical keys (compatible with `load_pnas_data()`):
- `images_train`: (N_train, H, W, 1) float32
- `images_val`: (N_val, H, W, 1) float32
- `images_test`: (N_test, H, W, 1) float32
- `responses_train`: (N_train, 41) float64
- `responses_val`: (N_val, 41) float64
- `responses_test`: (30, 30, 41) float64

The pipeline auto-detects `n_px_side` from the image shape (H == W).
